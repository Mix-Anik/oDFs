# Vanilla functions identified during the undocumented-function survey (qagame)

Script idea: parse the `0x<addr> 0x<size> <hash>` rows at the top of `qagame.dis`, drop hashes found in `baseq3-game-functions.hmap`, drop addresses mentioned in any `disasm/**/*.md`; ~60 remained after the first round, sorted by size. These were checked by embedded strings / call structure and are **vanilla-shaped (no DeFRaG-specific behaviour found; nothing to port)** — their hashes only differ from the baseq3 hmap (different compiler flags/data layout, e.g. `g_gravity` read through a helper):

## `0xf11` = `SetLeader(team, client)`, `0xfcb` = `CheckTeamLeader(team)` (vanilla; worklist pass 2)
Read in full: `0xf11` (callers `0x1063` = `CheckTeamLeader` region? and `0x1e0fb` = team-vote handler) prints `"%s is not connected"` / `"%s is not on the team anymore"` / `"%s is the new team leader"` through `0xee6` (= PrintTeam, per its use here; body not read), clears `sess.teamLeader` (`client+0x2a0`) of all other members of `sessionTeam` (`client+0x284`) calling `0x1ccdf` (= `ClientUserinfoChanged`, by use), then sets it for `client`. `0xfcb` (called from `0x1e0fb`... and the CheckTeamLeader users) searches for an existing leader, else picks the first non-`SVF_BOT` (`svFlags & 8` at `g_entities+0x1a8` area) member, else the first member. Identical to oDFs `g_main.c` `SetLeader` / `CheckTeamLeader`; the hash mismatch is presumably the different `gclient_t` stride (`0x37c`) — hash reason not verified. Nothing to port (no CTF/team leaders in DeFRaG runs).

## `0x629b` = bg_lib `AddString` (printf helper) — worklist pass 3
Evidence: literal `"(null)"` substituted when the string arg is NULL (and precision forced to -1); otherwise length = scan up to `prec` chars (`prec >= 0`) or `strlen` (`0x5bfc` = strlen, by this use: called with the string, result used as the length); then `width -= size` and a per-char copy/pad loop writing through `*buf_p` (`char **`, arg0) — i.e. the string branch of Q3's `vsprintf` in `bg_lib.c` (`AddString( char **buf_p, int *max, char *string, int width, int prec )` in the ioq3 variant; the 6-argument-word frame here suggests that shape, exact signature not verified). Called from `0x633c` (the vsprintf-style formatter, `%s` case — not read). Nothing to port: oDFs compiles its own `bg_lib.c` (and the QVM-only `sqrtf`/log/pow fixes already live there). Neighbours in the same address range (`0x6175`, `0x5bfc`, `0x633c`) are the rest of the C library and are the natural next group if wanted.

## `0x990` = DeFRaG `ExitLevel` (worklist pass 4) — differs from vanilla
Called from `0xb1a` (CheckExitRules path) and `0x14d88`; calls `0x14d4e` (BotInterbreedEndMatch, by position/use) first. Body: `g_gametype (0x1b1ec) == 1` (tournament): if `!level.restarted` -> `0x4f6` (RemoveTournamentLoser, by position), `map_restart 0`, `level.restarted = 1`, `0x12c69c = 0` (changemap), `0x12c698 = 0` (intermissiontime), return. Otherwise: **`vstr nextmap` unconditionally** — the vanilla `nextmap == "map_restart 0" && d1 != ""` -> `vstr d1`/`nextmap = "vstr d2"` chaining is ABSENT — then `changemap = intermissiontime = 0`, `teamScores[RED/BLUE] (0x12a320/24) = 0`, `PERS_SCORE (client+0xf8) = 0` for all CON_CONNECTED (2) clients, `0x24825(0)` (= G_WriteSessionData; DeFRaG's takes one argument, meaning not decoded), then CON_CONNECTED -> CON_CONNECTING (1).
oDFs: PORTED the single difference (g_main.c `ExitLevel`: removed the d1/d2 branch). Effect only for servers whose `nextmap` is `map_restart 0` AND which define `d1`; negligible. Revert = restore the `Q_stricmp( nextmap, "map_restart 0" ) && Q_stricmp( d1, "" )` block. Syntax-checked.

## `0x24e4d` = `UpdateIPBans`, `0x24fab` = `G_ProcessIPBans` (worklist pass 5) — older-Q3 variant
`0x24e4d` (callers `0x24f55`, `0x25021` = AddIP / RemoveIP-style handlers): walks the filter table at data `0x19aca0` (8-byte entries, `compare` at +0; entries with `compare == 0xffffffff` are skipped), formats each as `"%i.%i.%i.%i "` from the four `compare` bytes and appends to the `g_banIPs` cvar value (1024-byte buffer, `strlen` = `0x5bfc`, `Com_sprintf`-like `0xac0d`). **There is no per-byte wildcard (`*`) handling** — the stock-1.32 / ioq3 version (which oDFs `g_svcmds.c` has) prints `*` for each mask byte != 255. So DeFRaG round-trips `g_banIPs` through a lossy writer: a `10.1.*.*` ban is stored in the cvar as `10.1.0.0 ` (the mask is lost until the next `G_ProcessIPBans`). `0x24fab` (called from `G_InitGame` at `0x2bb`, no args) reads `g_banIPs` (`trap_Cvar_VariableStringBuffer` on `0x18ff0`, 0x400 bytes) and re-adds every token — not read beyond its prologue.
Not ported: it is a limitation (arguably a bug), and oDFs's ioq3-style wildcard writer is strictly better. Both functions are otherwise behaviourally the Q3 IP-ban filter list.

## `0x1656` = `FileCopy(src, dst)` — no callers (dead utility) (worklist pass 6)
Opens `src` for read (`FS_FOPEN` trap `-0xb`, mode 0) and `dst` for write (mode 1); on failure prints `"Warning: failed to open %s for copy. (source)"` / `"... (destination)"` (via `0x45a`, the `"%s"` print helper) and returns 0 (closing the source with `-0xe`); then loops reading chunks of `0x7d00` = 32000 bytes (`FS_READ -0xc`, then `FS_WRITE -0xd`) until the remaining length (`gei 0` loop on `len - 32000`) is exhausted, closes both, returns 1. The `.txt` literal at `0x7d00` in the disassembly is only a mis-annotation of the constant 32000 (a string pool address coincides). Searched for callers (`const 0x1656` exact-address match, excluding `0x1656d`): **none**, so it is unreferenced in qagame — a leftover from DeFRaG's old config-copy code. Not ported.

## Spawn-table sweep (worklist pass 7)
Method (script kept in the session scratchpad, easy to redo): from `qagame.dis` take the data words at `0x2604..0x27d4` as `(name_ptr, spawn_fn)` pairs, resolve `name_ptr` through the `0x0000xxxx  "name"` string-pool lines, then read each spawn fn's `ent->use` store (`const 0x2c4; add; const <fn>; store`) and compare the use fn's hash against `baseq3-game-functions.hmap`. Result: class set identical to oDFs; use fns that are NOT vanilla: `target_give` `0x252fc` (done, `G_TRIGGER/target_give.md`), `target_print` `0x25485` (= cpsm, done above), `target_score` `0x25457` (**unread**), `target_teleporter` `0x25881` (done, `G_TRIGGER/target_teleporter.md`), timer/frags/init/smallprint/speed (done earlier). Vanilla use fns: `target_remove_powerups`, `target_relay`, `target_kill`, `func_timer`.

## Worklist pass 8 — remaining small qagame fns (all low value)
- `0x1d997(arg0, arg1, ...)` (called from `0x1d9fe`, `0x1db30`): appends `trap_Argv(i)` (`-0xa`, 0x400 buffers) strings with separating spaces into a 0x400 buffer, guarding `len < 0x3ff` — the shape of vanilla `ConcatArgs(start)`; compiled differently/with an extra parameter (`arg1` = destination?), so the hash differs. Used by the `Cmd_Say`/`Cmd_Tell` family at `0x1db30`/`0x1d9fe`.
- `0x64f2`, `0x184e`, `0x17b7`: C-library / file-helper code (`0x64f2` is a `%`-format scanner — `vsprintf` neighbour, called from `0x246ee` session read etc.; `0x184e` is a string scan over an argument list; `0x17b7` splits a path on `"/"` via FS trap `-0x27` into an `0x2000` buffer — file listing). No DeFRaG-specific game logic.
- `0x264d5`, `0x26d7a`, `0x26dab`, `0x26cdb`, `0x26e39`, `0x2647d`: CTF (`g_team.c`) — `Team_*` flag sound/capture/return code (`"%s^7 returned the %s flag!"`, `Team_CaptureFlagSound`, `PrintMsg`). Not used by DeFRaG's modes; oDFs carries the stock versions.
- `0x2b5c…`: inside `target_init`'s use fn (`0x2aa8`), already documented in `G_TRIGGER/target_init.md`.
Conclusion: the qagame survey worklist now contains no remaining DeFRaG-specific *game-logic* function; remaining unreferenced hash-DIFF functions are C-library and CTF code. Further RE value is in cgame (client-side features: CGAZ `0x1cd86`/`0x2a12`, accel meter numerics, checkpoints `0x4f9d..`) and the ui demo browser — neither affects the oDFs qagame, since players run the original DeFRaG cgame/ui.
