# `func_0x20998` — missile trigger-touch handler (structurally identical to `G_TouchTriggers`, but missile-only)

**Address:** `0x20998`
**Stack frame:** `enter 0x10a4`
**Called from:** **not located anywhere in the bytecode.** No instruction
anywhere in `qagame.dis` pushes the literal constant `0x20998` (checked via
full-file text search, both as a `call` target and as a stored
pointer/callback value). This function nonetheless has its own entry in
DeFRaG's top-level function-hash table (`0x00020998  0x163  2074cba`), so it
is a real, intentionally-compiled function, not a decoding artifact. How it
is actually invoked is an **open question** — see "Open questions" below.
**Args:** 1 effective arg (`ent`, a `gentity_t*`); declared with a larger
arg slot but only `arg0` is read.

This was found while searching for the generic `G_TouchTriggers` (see
[`../G_UTILS/README.md`](../G_UTILS/README.md#g_touchtriggers-open-question--two-candidates-ruled-out-both-now-fully-decoded)):
a full sweep of every `trap_EntitiesInBox` (`trap -0x21`) call site in the
entire QVM turned up exactly 6 real sites (2 earlier apparent hits,
`0x3d57`/`0x12d98`, turned out to be false positives — the same bit pattern
`-0x21` used as a plain bitmask constant in a `band`, not a trap call).
This function is one of the 6, and the only previously-unaccounted-for one.

## Verdict: this is a real touch-trigger dispatcher — but scoped to missiles only

The function's very first two instructions gate its *entire* body on
`ent->s.eType == 3` (vanilla `ET_MISSILE`, consistent with the already-used
`ET_GENERAL=0/ET_PLAYER=1/ET_ITEM=2/ET_MISSILE=3` ordering elsewhere in this
project): if not a missile, it immediately `leave`s with return value `1`
and does nothing else. **All of the logic below only runs for missile
entities.** This means it is **not** the generic per-player
`G_TouchTriggers` that's still being searched for — but it is a genuine,
previously-undocumented sibling: DeFRaG missiles touch nearby trigger
entities (calling their `->touch` the same way a player would) as they fly,
which vanilla Q3 missiles do not do at all.

```c
int func_0x20998( gentity_t *ent ) {
    if ( ent->s.eType != 3 /* ET_MISSILE */ )
        return 1;

    // box: ent->r.currentOrigin (+0x1e8/+0x1ec/+0x1f0, confirmed) ± 6.0 on every axis
    //   (data-pool floats at 0x2450/0x2454/0x2458, all independently confirmed = 6.0f)
    vec3_t mins = { origin[0]-6.0f, origin[1]-6.0f, origin[2]-6.0f };
    vec3_t maxs = { origin[0]+6.0f, origin[1]+6.0f, origin[2]+6.0f };

    count = trap_EntitiesInBox( mins, maxs, list, 0x400 );   // trap -0x21, confirmed

    for ( i = 0; i < count; i++ ) {
        gentity_t *hit = &g_entities[ list[i] ];    // base 0x1b2f0, stride 0x43c

        // DeFRaG-added pre-filter, NOT in vanilla G_TouchTriggers:
        ptr = hit->UNCONFIRMED_0x324;                // new/unconfirmed field
        if ( ptr != NULL && *(int*)(ptr+0x24) == 9 )  // new/unconfirmed field+offset
            continue;

        if ( !trap_EntityContact( mins, maxs, hit ) )  // trap -0x22, confirmed by
            continue;                                   // enum-counting (see below)

        if ( (hit->UNCONFIRMED_0x2bb_flags /* +0xcc, new/unconfirmed */ & 0x10) == 0 )
            continue;
        if ( hit->touch /* +0x2c0, already project-confirmed */ == NULL )
            continue;

        trace_t trace;
        memset( &trace, 0, 0x38 );                     // trap -0x65, confirmed elsewhere
        hit->touch( hit, ent, &trace );                 // <-- the actual touch dispatch

        // further per-hit bookkeeping (not fully decoded — see below): reads
        // hit+0x54/+0x58 (new/unconfirmed) as per-clientNum bitmask-style
        // fields, cross-referenced against an owner/ownerNum-style chain
        // read from ent+0x29c/+0x304/+0x200 (all new/unconfirmed) — looks
        // like a "don't re-notify the same owner twice" dedup, structurally
        // reminiscent of (but with different offsets than) G_UseTargets's
        // already-documented per-frame dedup fields
        // (../G_UTILS/G_UseTargets.md).
    }

    SetLGKnockback();   // 0x4290, already project-confirmed
    SetGrappleMode();   // 0x42b5, already project-confirmed
    return 1;
}
```

### Confirmed building blocks (not re-derived, cited from elsewhere in this project)

- `+0x1e8`/`+0x1ec`/`+0x1f0` = `r.currentOrigin` — established throughout this project.
- `+0x2c0` = `touch` function pointer, called as `touch(self, other, trace*)` — already independently confirmed in [`Touch_Item.md`](../G_ITEMS/Touch_Item.md), [`RespawnItem.md`](../G_ITEMS/RespawnItem.md), [`func_0x1a1b2.md`](../G_ACTIVE/func_0x1a1b2.md), [`G_ACTIVE/README.md`](../G_ACTIVE/README.md).
- `trap -0x21` = `trap_EntitiesInBox`, `trap -0x65` = a `memset`-style clear — both already established.
- `0x4290`/`0x42b5` = `SetLGKnockback`/`SetGrappleMode` — confirmed in [`../G_ACTIVE/LG_Knockback.md`](../G_ACTIVE/LG_Knockback.md) / [`../G_ACTIVE/GrappleMode.md`](../G_ACTIVE/GrappleMode.md).

### `trap -0x22` = `trap_EntityContact`, confirmed this pass against oDFs's own `g_public.h`

Using the same index-counting technique already used for `G_LINKENTITY`/
`G_UNLINKENTITY`/`G_ENTITIES_IN_BOX` (see
[`../G_ACTIVE/GrappleHookMover.md`](../G_ACTIVE/GrappleHookMover.md)):
`G_ENTITY_CONTACT` is the very next entry after `G_ENTITIES_IN_BOX` in
[`../../code/game/g_public.h`](../../code/game/g_public.h) — index 33 →
trap `-(33+1) = -0x22`, matching exactly. This call shape
(`EntitiesInBox` broad-phase, then `EntityContact` narrow-phase, then a
`touch` callback) is the textbook vanilla `G_TouchTriggers` pattern.

## New/unconfirmed fields found (not documented elsewhere in this project)

| Offset | Observation | Confidence |
|---|---|---|
| `hit+0x324` | Pointer field; if non-null and `*(ptr+0x24)==9`, the candidate is skipped entirely (pre-filter before the contact test) | New, not confirmed |
| `hit+0xcc`, bit `0x10` | Flag tested right before the `touch` dispatch — structurally plausible fit for a `contents`-style bitmask (vanilla `G_TouchTriggers` checks `CONTENTS_TRIGGER`), **not independently confirmed** | New, structural guess only — flagged, not asserted |
| `hit+0x54`, `hit+0x58` | Read after the touch call, bit-tested against a computed index; a 64-bit per-`clientNum` bitmask (**confirmed this project** — see [`../G_CLIENT/func_0x2830.md`](../G_CLIENT/func_0x2830.md): `func_0x1629`/`func_0x15fa`, called from `func_0x2830` on client (re)spawn, are a "clear my bit" accessor pair for this exact field pair) | Shape/identity-as-bitmask confirmed; this function's own specific *use* of it (what being bit-set here means) still not confirmed |
| `ent+0x29c`, `ent+0x304`, `ent+0x200` | Read in the post-touch bookkeeping block; appear to be an owner/ownerNum-chain lookup | New, not confirmed |

None of these were decoded to full certainty this pass — the touch-dispatch
mechanism itself (the part answering the `G_TouchTriggers` search) is solid;
the surrounding dedup/ownership bookkeeping is not.

## Open questions

- **How is this function actually invoked?** Exhaustively searched and
  came up empty on every angle tried:
  - No `const 0x20998 / call -1` anywhere in the CODE segment (direct call).
  - No `const 0x20998 / jump -1` anywhere either (tail-call).
  - No occurrence of the literal `0x20998` (in any of the forms this
    disassembler renders a dword — including as an annotated raw-byte
    comment) anywhere in the **full** DATA segment dump (`0x0`–`0x28c8`,
    checked end to end, not just spot-checked) or the LIT segment. A
    function-pointer table entry pointing at this function would have to
    show up as a literal `0x20998` dword somewhere in DATA for a `load4`
    elsewhere to later retrieve and call it — none exists.
  - This function's hash-table entry (size `0x163` = 355 instructions) is
    real and intentional — this isn't a decoding artifact.
  - Checked whether any of this function's distinctive internal field
    offsets (e.g. `+0x324`) are unique to it, which might hint at a
    sibling dispatcher reading the same data — they're not; `+0x324` alone
    has 65 other unrelated uses throughout the QVM, so that angle doesn't
    narrow anything down either.

  **Conclusion: this function's caller cannot be located via static
  analysis of this disassembly.** The most plausible remaining
  explanations, in order of likelihood, are: (a) it is genuinely dead code
  — compiled in (hence the real hash-table entry) but never wired up,
  perhaps an abandoned or disabled DeFRaG experiment; (b) it's reached via
  some QVM calling mechanism this disassembler doesn't render as literal
  text (not identified, no evidence for this found); (c) a relocation or
  table mechanism outside what `qagame.dis` exposes. Not resolved further
  — flagged as a dead end for future passes rather than actively pursued.
- **The generic, per-player `G_TouchTriggers` is still not located.** This
  function is missile-only (gated on `eType==3`); it does not explain how
  players trigger generic (non-race) triggers. The two other
  `EntitiesInBox`-shaped candidates already ruled out
  (`G_KillBox`, the grapple-hook mover) and this one being missile-scoped
  means **zero** of the 6 real `EntitiesInBox` call sites in the entire QVM
  is a confirmed generic player-side `G_TouchTriggers`. Either it's been
  restructured into one of the already-decoded large functions under a
  different mechanism (not using `EntitiesInBox` at all), or it genuinely
  still hasn't been found. Flagged, not guessed at.
- The pre-filter (`hit+0x324`/`+0x24==9`) and post-touch dedup block
  (`hit+0x54`/`+0x58`, `ent+0x29c`/`+0x304`/`+0x200`) are not decoded to
  completion — a future pass could pin these down.

## oDFs implementation status

**Not implemented.** This is a newly-found DeFRaG mechanic (missiles
touching trigger entities while flying) with no vanilla counterpart and no
existing oDFs analog. Out of scope for the current `G_TouchTriggers` search
(which was looking for the generic player-side function); left for a future
pass, together with pinning down the unconfirmed fields above and — ideally
— finding this function's real caller.
