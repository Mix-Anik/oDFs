# DeFRaG CHS ("crosshair stats") panels — `df_chs0_*`, `df_chs1_*`, `df_chs2_*` (iter 40, decode only)

Found while looking for the consumer of the OB predictor results (`0xb21d`): the predictions are only DISPLAYED through the CHS panels (item ids 50-77 and 300-310). The CHS system is a configurable HUD list of up to 8 "info" items per panel.
Pseudo-C (via `disasm/tools/qdec.py`): `chs_rows_qdec.txt` (= `0xc320`, 1773 statements), `chs_draw_qdec.txt` (= `0xf53c`), `chs_isselected_qdec.txt` (= `0xbc67`); the 356-entry item table in `chs_items.txt` (`id | label | value format+args`, extracted from the jump table at data `0x1af0`; blank rows = unused ids).

## Architecture
- **Cvars** (per panel p = 1, 2; `df_chs<p>_`): `Draw` (when to draw: same 0..4 semantics as `df_accel_Draw`, via `0x8f3a`), `FontSize`, `FontShadow`, `FontColor`, `FontTransparency`, `LabelColor`, `LabelType`, `DisplayType`, `OffsetX`, `OffsetY`, `EnableCombos`, `ComboSeparator` (string), `Info1`..`Info8`. Panel 0 (`df_chs0_*`) has no Info/Label cvars (`Draw FontSize FontShadow FontColor FontTransparency LabelColor DisplayType OffsetX OffsetY`): a fixed single display, draw function not located yet. `df_chs_UsePredicted` is shared (pos/vel/angles from predictedPlayerState or snap->ps).
- **`0xf53c(panel)`** draws a panel (1 or 2 only here): reads the panel's Draw/size/etc. cvars (panel 1 base `0x128dc4`.., panel 2 `0x127884`..), gates with `0x8f3a(Draw)`, then for each of the 8 rows: `Info<n>` cvar string (`0xf332`) -> if `EnableCombos`, tokenises it with `ComboSeparator` (up to `0x196c` = 10 items per combo, ids parsed by `atoi` with an optional leading `-` meaning "no label"), else a single id; each id is rendered by `0xc320(id, labelBuf, valueBuf, ...)` into label/value strings (`0x782f` = Com_sprintf into buffers, "%i %i"/"%s"/"%.3f" formats); then the strings are drawn with `CG_DrawStringExt` (`0x1d330`) at the panel position (screen centre `320/240` + OffsetX/Y, adding `FontSize` rows), `LabelType`/`DisplayType` (0..4, jump table at data `0x206c`) select label-left/value-right, stacked, or in-line layouts.
- **`0xbc67(panel, id)`** = "is item `id` currently selected in this panel's Info1..8" (used by the data trackers to run only when needed).
- **`0xc320(id, ...)`**: `id = group*1000 + item`: `group = id / 1000` (<= 6 = number of combos/format variants) and `item = id % 1000` indexes the 356-entry switch (`chs_items.txt`).

## Iter 41 — panels 1/2 PORTED (`code/cgame/cg_dfchs.c`) + decode details
- `0xc320(id, labelBuf, valueBuf, extraBuf, sep)`: `id = decimals*1000 + item` (`id/1000` = decimals, capped at 6 (`0x1968`), value format `"%<dec+1>.<dec>f"`); `item = id % 1000`. Item cases fill label + value (the speed item replaces its value by the HUD speed text `0x41b6`).
- `0xbe67(panel, rows[8])` layout (56-byte rows): clamps FontSize 4..50, FontShadow to 0/1 (else 1), alpha to [0,1] (else 1.0), offsets +-320/+-240; colours `g_color_table[(cvar&15)%10]`; **DisplayType**: 0 = ring of eight around the screen centre (dx/dy = (0,-18),(15,-10),(18,0),(15,10),(0,18),(-15,10),(-18,0),(-15,-10), y shifted by -size/2, aligns 2,1,1,1,2,3,3,3), 1/2/3 = one column at x=320 from y = 240-(4*size+16), pitch size+4, align = type, 4 = two columns (rows 0-3 at x=303 right-aligned, rows 4-7 at x=337 left-aligned, y from 240-(2*size+8)).
- `0xf4b9(align, x, size, len)`: 1 -> x - size/2, 2 -> centred `x - size/2 - (len-1)*size/2`, 3 -> right `x - size/2 - (len-1)*size`.
- **LabelType** (jump table `0x205c`): 0 value only (FontColor); 1 `label: value`; 2 rows 0-3 `value :label`, rows 4-7 `label: value`; 3 the reverse; 4 always `value :label` (labels in LabelColor; `": "` = fmt `"%s "` of `":"`, `" :"` = fmt `" %s"`).
- **Combos** (`EnableCombos`): the `Info<n>` cvar string is a COM_Parse token list (up to 10): a token is an item id (|atoi|), a `-` prefix forces label type 0, or `$cvar` expands to the cvar value (then label = `$cvar`, value = expansion); results are joined with `ComboSeparator` (label/value strings accumulated separately, capped at 128 chars).
- Gate: `df_chs<p>_Draw` uses the same semantics as `df_accel_Draw` (`0x8f3a`, exported here as `CG_DF_DrawAllowed`).
- oDFs: cvars `df_chs0/1/2_*` (defaults from the DeFRaG table; panel 0 registered only), drawing of panels 1 and 2 from `CG_Draw2D` (independent of `df_hud`). Items ported: 1-6, 20-25 (X/Y/Z/XY/XYZ/F), 30-38 (angles, position, view position), 111 ping, 117/118 name, 171 cg.time. Others print nothing. Panel-2 font cvars are shared with the accel meter (`dfChs[2].*`; df_accel previously defined its own copies, removed). Syntax-checked, visually untested. Revert: remove the two `CG_DF_DrawChs` calls (cg_draw.c) and `cg_dfchs.c` from CMakeLists.

## Iter 56 — items 160-163 (savepos distances) PORTED
The cvar named by `saveposname` holds the stored command line (`placeplayer x y z ...`, written by `savepos`); if its first token is `placeplayer`, the next three tokens (parsed with **atoi**, DeFRaG truncates) minus the current position give the deltas; otherwise all deltas are 0. Value text `[ <posname> ] = <number(s)>`: 160 XY, 161 Z, 162 XYZ, 163 `XY<sep>Z<sep>XYZ` (labels `savepos dist XY/Z/XYZ`). 151-153 (input variants with other glyph sets) and 190-193/215/216/225/227/233/ghost items remain unported. Syntax-checked, untested.


## Iter 57 — CHS panel 0 (`0xfde7`) DECODED & PORTED: movement-key display
Panel 0 is not an info list: it draws the pressed movement keys around the crosshair (centre `(320+OffsetX-size/2, 240+OffsetY-size/2)`, size 4..50, alpha [0,1] else 1). Pressed keys use `df_chs0_FontColor`, released keys `df_chs0_LabelColor` (released keys are drawn only when the two cvar values differ), one character per key via CG_DrawStringExt (maxChars 1). Key masks from `ps.stats[13]`: 1 F, 2 B, 8 L, 16 R, 512 walk `_`, 32 jump `J`, 64 crouch `C`. **DisplayType** (jump table `0x2080`): 0 = diamond (F at y-size, B at y+size, L at x-size, R at x+size, walk/jump/crouch overlaid at the centre) with the arrow glyph codes 135/134/136/141; 3 = the same with letters F B L R; 5 = the same with the first letter (upper-cased `0x3260c`) of the key bound to `+forward/+back/+moveleft/+moveright` (`0x85a1` = `trap_Key_GetKey`, -63); 2 / 4 / 6 = keyboard layout (F at y-size, B at the centre, L/R beside B, J at (x-2size, y+size), walk at (x, y+size), C at (x+2size, y+size)) with arrow glyphs / letters / bound keys; 1 = strokes `/\`, `\/`, `<`, `>` made of slash characters (offsets size/4) plus the centre keys. Draw gate = `df_chs0_Draw` via `CG_DF_DrawAllowed`. oDFs: `CG_DF_DrawChs0` (cg_dfchs.c), called with `CG_DF_DrawChs( 0 )` from CG_Draw2D. Syntax-checked, visually untested. Revert: remove the call.
